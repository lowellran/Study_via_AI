### 🌟 【Plan 01 · 硬件底座】知识点 1.1：RCU 时钟总线与外设的心跳机制

在所有嵌入式新手最常踩的坑里，**“写了一大堆 GPIO 配置代码，结果引脚毫无反应”** 绝对排在第一位。这个问题的核心矛盾，就在于**漏开了 RCU 时钟**。

```
                       ┌───────── 外部高频晶振 (HXTAL, 8MHz)
                       │
[能量源泉] ────► [PLL 锁相环倍频] ───► [系统主时钟 (CK_SYS, 240MHz/168MHz)]
                                              │
                      ┌───────────────────────┴───────────────────────┐
                      ▼                                               ▼
            [AHB 高速高性能总线]                            [APB 外设总线]
        (SRAM / DMA / GPIO 快速通道)                   (USART / TIMER / I2C / SPI)
                      │                                               │
             [RCU 时钟门控开关]                             [RCU 时钟门控开关]
                      │                                               │
               [GPIOA/B/C/D...]                                [USART0, TIMER1...]
```

#### 1. 为什么芯片默认要把所有外设时钟关掉？
- **物质与能耗的矛盾**：微控制器（MCU）在出厂设计时，追求的是极致的低功耗。
- 芯片内部有几十个外设（GPIO、串口、定时器、ADC等）。如果一上电所有外设全部通电震荡，就像一栋大楼不管有没有人住，把所有房间的空调和灯全部开着一样，会产生巨大的功耗和发热。
- 因此，GD32 默认对所有外设施加了**“时钟门控（Clock Gating）”**——默认全处于沉睡断钟状态。

#### 2. RCU 是什么？
- **RCU (Reset and Clock Unit，复位与时钟控制单元)** 就是整个芯片的时钟与电源总管。
- 你想使用任何一个 GPIO 端口（比如 `GPIOA`、`GPIOB`），必须先向 RCU 申请：**“把通往这个端口的时钟总线大门打开！”**
- 代码实现只需要极其关键的一行：
  ```c
  // 必须在配置引脚前执行！使能 GPIOA 端口的时钟供给
  rcu_periph_clock_enable(RCU_GPIOA);
  ```

#### 3. AHB 与 APB 总线的形象比喻
你可以把芯片内部想象成一个现代化工业园区：
- **AHB（Advanced High-performance Bus）**：园区的主干高速公路，运载速度极快，连接着 CPU、内存（SRAM）以及需要频繁快速搬运数据的 GPIO 端口和 DMA。
- **APB（Advanced Peripheral Bus）**：园区的支线小路，连接着速度要求相对较低的外设（如串口 USART、低速定时器等）。
- **时钟信号**：就是公路上准点发车的班车。没有班车（没有时钟），外设里的数据和寄存器指令就根本无法运转流动。

### 📚 一、 专业英文术语“拆解速记库”

| 缩写 | 英文全称 | 词根拆解与字面含义 | 为什么叫这个名字？（秒记技巧） |
| :--- | :--- | :--- | :--- |
| **PP** | **P**ush-**P**ull | **Push** (推/向上送) + **Pull** (拉/向下拉) | **推挽输出**。由两个互补的 MOS 管组成，一个往高电平“推”，一个往低电平“拉”，驱动力最强。 |
| **OD** | **O**pen-**D**rain | **Open** (开路的/断开的) + **Drain** (漏极，MOS管的D极) | **开漏输出**。内部上方 MOS 管被断开，漏极悬空。只能往下拉低，无法主动推高，必须外接上拉电阻。 |
| **PU / PD** | **P**ull-**U**p / **P**ull-**D**own | **Pull-Up** (向上拉升) / **Pull-Down** (向下拉低) | **上拉 / 下拉**。内部用一个弱电阻连接到 3.3V (VDD) 或 0V (VSS)，防止引脚悬空时电平乱跳。 |
| **High-Z** | **High** **I**mpedance | **High** (高的) + **Z** (物理学中阻抗的符号) | **高阻态（浮空态）**。电阻极大，相当于断路。对外界既不给电也不吸电，处于“中立发呆”状态。 |
| **IDR** | **I**nput **D**ata **R**egister | **Input** (输入) + **Data** (数据) + **Register** (寄存器) | **输入数据寄存器**。CPU 读这个寄存器，就能知道当前引脚上外界输入的是 0 还是 1。 |
| **ODR** | **O**utput **D**ata **R**egister | **Output** (输出) + **Data** (数据) + **Register** (寄存器) | **输出数据寄存器**。CPU 往这个寄存器写 1，引脚就喷出高电平；写 0 就拉低到地。 |
| **AF** | **A**lternate **F**unction | **Alternate** (备用的/替代的) + **Function** (功能) | **复用功能**。引脚不当普通 GPIO 用，而是借给串口 TX/RX、PWM 定时器等专用外设。 |

### 🖼️ 二、 视觉全景解析：GPIO 内部硬件结构与输出模式对比

#### 1. 学术工程硬核版：GPIO 引脚内部结构原理图

![学术硬核版：GD32/STM32 GPIO内部结构图](C:/Users/24295/.gemini/antigravity/brain/b2d0bcfd-9968-49bc-a3cc-6de23e0ec02b/gd32_gpio_academic_1786500495596.jpg)

##### 🔍 核心电路模块拆解：
1. **右侧【ESD 保护二极管 (Protection Diodes)】**：
   - 保护引脚安全：当外部输入电压高于 VDD（3.3V）时，上方二极管导通将电流泄放到电源；当低于 VSS（0V）时，下方二极管导通保护内部芯片免遭静电（ESD）击穿。
2. **中间上方【输出驱动级 (Output Driver Control)】**：
   - **P-MOS 管**（接 VDD 3.3V） + **N-MOS 管**（接 VSS 0V）。
   - **推挽模式 (PP)**：P-MOS 和 N-MOS 协同工作。写 1 时 P-MOS 导通强推 3.3V；写 0 时 N-MOS 导通强拉 0V。
   - **开漏模式 (OD)**：P-MOS 被永久断开！写 0 时 N-MOS 导通拉低到 0V；写 1 时 N-MOS 也关闭，引脚处于**高阻态（High-Z）**，必须依赖上拉电阻才能拉升到高电平。
3. **左侧【输入滤波与施密特触发器 (Schmitt Trigger)】**：
   - 将外部输入的缓慢起伏、有杂波的模拟电压，整形为极其干净利落的 0 和 1 数字方波，存入 **IDR 输入数据寄存器**。
4. **左下角【模拟通道 (Analog Input Path)】**：
   - 当引脚配置为 ADC 采样时，**绕过施密特触发器**，原汁原味地把微弱模拟电压直接送入 ADC 转换器。

#### 2. 趣味形象比喻版：推挽 (PP) vs 开漏 (OD) 拔河大战

![趣味比喻版：推挽与开漏拔河对决](C:/Users/24295/.gemini/antigravity/brain/b2d0bcfd-9968-49bc-a3cc-6de23e0ec02b/gd32_gpio_cartoon_1786500580835.jpg)

##### 🥊 比喻图故事化拆解：
1. **左侧【推挽模式 Push-Pull】—— 强力超人兄弟（有推有拉）**：
   - 楼上有个超人（P-MOS 管），楼下有个超人（N-MOS 管）。
   - 要高电平？楼上超人双手使劲**向下强推（Push）3.3V 能量球**！
   - 要低电平？楼下超人双手死命**向下拉拽（Pull）到 0V 地面**！
   - **特点**：力量十足，上升沿和下降沿都极快，最适合驱动 LED、蜂鸣器、SPI 高速总线。
2. **右侧【开漏模式 Open-Drain】—— 独臂拉绳工（只拉不推）**：
   - 楼上的超人被解雇了！只有楼底下的工人在（N-MOS 管）。
   - 他**只能做一件事：把能量球拉进下水道（0V 低电平）**。
   - 当他松手时（写 1），能量球悬浮在半空处于**高阻态（High-Z 困惑迷茫）**。
   - **怎么输出高电平？** 必须在外部加一根**救援弹簧绳（外部上拉电阻 Pull-Up Resistor）**，把悬空的信号拉升到 3.3V！
   - **为什么需要这种看似“残缺”的模式？** 因为在 I2C 总线中，多个设备并联在同一根线上，如果大家都用推挽，一个推高一个拉低就会短路烧芯片（打架）；而用开漏，大家“只拉低、不强推”，就能实现完美的“线与”逻辑与双向通信！

### 📋 三、 GPIO 8 种模式速查大一统

在嵌入式实战中，GPIO 共有 4 种输入 + 4 种输出组合：

```
                ┌─── 1. 浮空输入 (Floating) ─── 无内部上下拉，电平完全由外部决定
                ├─── 2. 上拉输入 (Pull-Up) ──── 内部接弱上拉电阻，默认高电平
   【输入模式】 ├─── 3. 下拉输入 (Pull-Down) ── 内部接弱下拉电阻，默认低电平
                └─── 4. 模拟输入 (Analog) ───── 关掉施密特触发器，ADC 测量专用
GPIO 模式 ──┤
                ┌─── 5. 通用推挽输出 (Out PP) ── 强高强低，驱动 LED / 继电器
                ├─── 6. 通用开漏输出 (Out OD) ── 需外接上拉，支持电平匹配与 I2C
   【输出模式】 ├─── 7. 复用推挽输出 (AF PP) ─── 串口 TX / PWM 波形输出
                └─── 8. 复用开漏输出 (AF OD) ─── 硬件 I2C SCL/SDA 引脚专用
```

### 💻 四、 讲义代码与固件库函数对应

在 GD32 固件库中，模式配置由两个独立函数完成：

```c
// 1. 设置主模式：输入(INPUT) / 输出(OUTPUT) / 模拟(ANALOG) / 复用(AF)
// 并且在这里选择是否使能内部上下拉：GPIO_PUPD_NONE / GPIO_PUPD_PULLUP / GPIO_PUPD_PULLDOWN
gpio_mode_set(GPIOB, GPIO_MODE_OUTPUT, GPIO_PUPD_NONE, GPIO_PIN_2);

// 2. 如果是输出/复用模式，进一步设置输出特性：
// 输出类型：推挽(GPIO_OTYPE_PP) 或 开漏(GPIO_OTYPE_OD)
// 引脚翻转速度：2MHz / 25MHz / 50MHz / 200MHz
gpio_output_options_set(GPIOB, GPIO_OTYPE_PP, GPIO_OSPEED_2MHZ, GPIO_PIN_2);
```

##### 🔍 内外区别大白话总结：
1. **“内”（Inside MCU Chip）**：
   - 芯片制造厂在硅片晶圆（Silicon Die）上，就已经帮你集成了两个微小的弱电阻（大约 **30kΩ ~ 50kΩ**），分别连着 3.3V 和 0V，并各配了一个电子开关。
   - **特点**：不用你在外面焊零件，省钱省空间；但因为阻值大（弱上拉），上升沿速度稍慢。你在代码中写 `GPIO_PUPD_PULLUP`，就是用软件把芯片内部的小开关闭合。
2. **“外”（Outside PCB Board）**：
   - 芯片引脚从外壳引出后，硬件工程师用电烙铁在电路板（PCB）铜皮走线上，额外焊了一颗实体贴片电阻（如 4.7kΩ 或 10kΩ），连到电路板的 3.3V 电源上。
   - **特点**：阻值小、上拉力量强（强上拉），抗干扰能力极强，多用于高速 I2C 通信或长导线按键。

### 🧩 答疑二：`gpio_mode_set` 的内部上下拉，输出模式是否都选 `GPIO_PUPD_NONE`？

- **绝大多数推挽输出（Out PP）**：是的！确实都配置为 `GPIO_PUPD_NONE`。因为推挽模式下，内部的强力 MOS 管导通电阻只有几十欧姆，远远强于 40kΩ 的弱电阻，根本不需要弱上下拉多此一举。
- **但有两种特殊情况，输出模式也需要开启内部上拉（PULLUP）**：
  1. **开漏输出（Out OD）**：如果外部 PCB 没焊外置上拉电阻，又想输出高电平，就可以在代码里配置为 `GPIO_PUPD_PULLUP`，让芯片内部的弱电阻来帮忙把电平拉高！
  2. **复用开漏（AF OD，如 I2C 总线）**：如果硬件上偷懒没焊外部上拉电阻，也可以开启内部上拉应急。

### 🌟 【Plan 01 · 硬件底座】知识点 1.3：LED 驱动电路 —— 灌电流 (Sink) vs 拉电流 (Source)

在嵌入式开发中，点亮一颗 LED 看起来最简单，但电路设计却有两种截然相反的哲学：**是由 MCU 往外“喷电”，还是 MCU 往里“吸电”？**

---

### 📚 一、 专业英文术语“拆解速记库”

| 缩写 / 术语 | 英文全称 | 词根拆解与字面含义 | 为什么叫这个名字？（秒记技巧） |
| :--- | :--- | :--- | :--- |
| **Source Current** | **Source Current** | **Source** (源泉/发源地) + **Current** (电流) | **拉电流（推电流/输出电流）**。MCU 引脚充当电源源头，主动往外部负载**喷出电流**。 |

##### 🔍 核心电路参数拆解：
1. **左侧【拉电流接法 (Source Current / Active-High)】**：
   - 引脚接 LED **正极（阳极 Anode）**，LED 负极（阴极 Cathode）经限流电阻接地。
   - **点灯逻辑**：引脚写 1（高电平），内部 P-MOS 导通，电流从 MCU 喷出点亮 LED；写 0 灭灯。
   - **限流电阻计算公式**：
     $$I = \frac{V_{CC} - V_F}{R} = \frac{3.3\text{V} - 2.0\text{V}}{1000\Omega} = 1.3\text{mA}$$
2. **右侧【灌电流接法 (Sink Current / Active-Low，最推荐！)】**：
   - 外部 3.3V 电源接限流电阻和 LED **正极**，LED **负极**接 MCU 引脚。
   - **点灯逻辑**：引脚写 0（低电平），内部 N-MOS 导通把引脚接地，电流从外部 3.3V 灌入引脚沉入 GND，LED 点亮！写 1 时两端等电位，LED 熄灭。
   - **为什么工业上极度偏爱灌电流？** 因为在硅芯片制造工艺中，N-MOS 管的导通内阻更小、载流子迁移率高，单片机引脚**“吃电流（灌电流）”的能力远大于“吐电流（拉电流）”的能力**！

### 📚 一、 引脚英文与软件思维映射 (G、D、S)

### 🎯 三、 3 秒看懂原理图符号与选型法则

#### 1. 怎么根据原理图图形一眼区分 N 还是 P？（看箭头与小圆圈）
- **看箭头方向**：
  - **箭头向内指（Pointing IN）** $\rightarrow$ **NMOS**（记忆法：**N** $\rightarrow$ **I**n，往里钻）。
  - **箭头向外指（Pointing OUT）** $\rightarrow$ **PMOS**（记忆法：**P** $\rightarrow$ **P**ointing away，往外跑）。
- **看 G 极有没有小圆圈（Bubble）**：
  - G 极连线上带一个小圆圈 $\rightarrow$ **PMOS**（数字逻辑中圆圈代表“低电平有效/取反”，给 0 打开）。
  - G 极没有圆圈，光秃秃的 $\rightarrow$ **NMOS**（高电平有效，给 1 打开）。

---

#### 2. 电流往哪走？负载（LED）放在哪个极？

这是软件人最容易懵的地方，记住一句话：**“S 极是基准不动产，负载永远接在 D 极上！”**

##### 🔹 NMOS —— “低端开关 (Low-Side Switch)”（负责管接地）
- **接法**：
  - **S 极 (Source)** $\rightarrow$ 必须死死**接在 GND (0V 地面)**。
  - **D 极 (Drain)** $\rightarrow$ 接你的负载（LED 负极），LED 正极接 3.3V/5V。
  - **G 极 (Gate)** $\rightarrow$ 接单片机 GPIO。
- **工作机制**：
  - 单片机输出 **HIGH (3.3V 高电平 / 1)**：NMOS 内部导通，把 D 极拉到地面（接地），电流从 3.3V $\rightarrow$ LED $\rightarrow$ D极 $\rightarrow$ S极 $\rightarrow$ 流入 GND，**LED 点亮！**
  - 单片机输出 **LOW (0V / 0)**：NMOS 关断，通路切断，LED 熄灭。

##### 🔹 PMOS —— “高端开关 (High-Side Switch)”（负责管供电）
- **接法**：
  - **S 极 (Source)** $\rightarrow$ 必须死死**接在 VCC (3.3V/5V 楼顶电源)**。
  - **D 极 (Drain)** $\rightarrow$ 接你的负载（LED 正极），LED 负极接 GND。
  - **G 极 (Gate)** $\rightarrow$ 接单片机 GPIO。
- **工作机制**：
  - 单片机输出 **LOW (0V 低电平 / 0)**：PMOS 内部导通，把 3.3V 从 S 极放行到 D 极，电流从 3.3V $\rightarrow$ S极 $\rightarrow$ D极 $\rightarrow$ LED $\rightarrow$ 流入 GND，**LED 点亮！**
  - 单片机输出 **HIGH (3.3V / 1)**：PMOS 关断，电源断开，LED 熄灭。

#### 3. 终极选型：什么时候选 NMOS？什么时候选 PMOS？

| 业务场景 | 最佳选型 | 为什么这么选？（底层逻辑） |
| :--- | :--- | :--- |
| **控制电机、继电器、LED、蜂鸣器通断** | **首选 NMOS (低端开关)** | **性能好且便宜**。NMOS 的电子迁移率高、导通内阻极小、发热极低，是工业上用量最大、最省钱的开关方式。 |
| **给某个传感器模块/芯片进行彻底“断电休眠”** | **选 PMOS (高端开关)** | 如果用 NMOS 断地线，传感器芯片虽然不工作，但内部很多引脚可能通过上拉电阻从其他芯片“偷电（寄生供电）”，导致系统异常。所以切断整板电源正极时用 PMOS 最干净！ |
| **单片机内部推挽输出 (Push-Pull)** | **NMOS + PMOS 组合** | 上方用 PMOS 管管住 3.3V 负责“推高”，下方用 NMOS 管管住 GND 负责“拉低”，两者互补！ |

## 附录：Plan 01 一页速查表 (One-Page Cheat Sheet)

> **一句话定义**：GPIO 是单片机输入输出数据的物理通道，必须先在 RCU 开启对应时钟“接通电源电闸”，通过内部 P-MOS 与 N-MOS 的开闭控制推挽（强强驱动）或开漏（拉低导通、悬空断路）模式。

### 核心概念归纳
1. **RCU 时钟使能**：
   - 寄存器/外设本质是电极存储器，无时钟供应即处于死寂断电状态，读写均无效。
   - 函数：`rcu_periph_clock_enable(RCU_GPIOx);`
2. **GPIO 8 种工作模式**：
   - 4种输入：`GPIO_MODE_INPUT`（浮空 NONE、上拉 PULLUP、下拉 PULLDOWN、模拟 ANALOG）
   - 4种输出：`GPIO_MODE_OUTPUT` / `GPIO_MODE_AF`（推挽 PP、开漏 OD）
3. **推挽 (Push-Pull) vs 开漏 (Open-Drain)**：
   - **推挽 PP**：P-MOS 与 N-MOS 均工作，写 1 强推 3.3V，写 0 强拉 0V。支持灌电流与拉电流。
   - **开漏 OD**：P-MOS 被彻底禁用，写 0 时 N-MOS 导通接地（0V），写 1 时 N-MOS 截止呈现高阻态（悬空）。需外部上拉方可输出高电平。
4. **电路底层反相逻辑**：
   - 软件写 0 ==> 芯片内部反相电路（非门）输出高电平 ==> N-MOS 栅极得电导通 ==> 引脚接地输出 0V。

### 易错红区 (Pitfalls)
1. **漏开 RCU 时钟**：操作 GPIO 前未执行 `rcu_periph_clock_enable()`，导致 GPIO 状态始终为复位默认值。
2. **按键浮空**：无外部上拉/下拉硬件电路时选 `GPIO_PUPD_NONE`，引脚受外界电磁干扰导致按键抖动误触发。
3. **开漏模式以为能强推高电平**：开漏模式下写 1 输出高阻态，无上拉电阻时无法主动输出 3.3V。

### 使用前检查清单 (Checklist)
- [ ] 是否使能对应 GPIO 的 RCU 时钟（`RCU_GPIOA/B/C...`）？
- [ ] 按键/传感器引脚的 PUPD 参数是否匹配硬件物理电路（按键接地配上拉 PULLUP，按键接3.3V配下拉 PULLDOWN）？
- [ ] 灌电流/拉电流 LED 的写 0/写 1 逻辑是否正确？

1. 为什么开漏模式写 0 时 N-MOS 管是导通的？
2. 为什么给按键接地电路配置 `GPIO_PUPD_NONE` 会导致电平不稳定？
3. 如果漏写 `rcu_periph_clock_enable(RCU_GPIOC)`，读取 PC13 会返回什么？
4. 推挽输出和开漏输出内部最大的结构差异是什么？
5. 为什么说“开漏模式下写 1 相当于断路”？
